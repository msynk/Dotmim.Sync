Snapshot
=========================

Overview
^^^^^^^^^^^

When a brand-new client connects, the server has to read every row from every synced table to build the initial payload. With large databases this is slow, especially over HTTP where the client may time out before the server is done.

Snapshots solve this. A snapshot is a precomputed initial payload, generated by the server, that any new client can apply directly. Initialization becomes:

1. The new client downloads and applies the snapshot taken at time **TS**.
2. The new client makes a regular sync to catch up with everything that happened between **TS** and now.

A common pattern is to regenerate the snapshot on a schedule (every couple of weeks, every night, etc.) so that initialization stays fast.

Server side
^^^^^^^^^^^^^^^^^^

Snapshots are produced by ``RemoteOrchestrator.CreateSnapshotAsync`` (or the equivalent on ``WebRemoteOrchestrator`` for HTTP scenarios where you do this from a separate worker).

.. code-block:: csharp

    var serverProvider = new SqlSyncProvider("Data Source=...");

    var setup = new SyncSetup(allTables);

    var snapshotDirectory = Path.Combine(Environment.CurrentDirectory, "snapshots");

    var options = new SyncOptions
    {
        SnapshotsDirectory = snapshotDirectory,
        BatchSize = 3000,
    };

    var remoteOrchestrator = new RemoteOrchestrator(serverProvider, options);

    var batchInfo = await remoteOrchestrator.CreateSnapshotAsync(setup);

The signatures available are:

.. code-block:: csharp

    public Task<BatchInfo> CreateSnapshotAsync(
        SyncSetup setup = null,
        SyncParameters syncParameters = null,
        IProgress<ProgressArgs> progress = null);

    public Task<BatchInfo> CreateSnapshotAsync(
        string scopeName,
        SyncSetup setup = null,
        SyncParameters syncParameters = null,
        IProgress<ProgressArgs> progress = null);

The output folder layout looks like this:

.. image:: https://user-images.githubusercontent.com/4592555/73745385-311c0900-4753-11ea-98d1-915df4bd2b9c.png

* One or more ``*.batch`` files containing the rows for each table.
* A ``summary.json`` describing the snapshot.

.. code-block:: json

    {
        "dirname": "ALL",
        "dir": "C:\\Snapshots",
        "ts": 2001,
        "parts": [
            {
                "file": "000_fnwkoou5_tdj.batch",
                "index": 0,
                "last": false,
                "tables": [
                    { "n": "ProductCategory" },
                    { "n": "ProductModel" },
                    { "n": "Product" }
                ]
            },
            {
                "file": "001_02zy0swq_nce.batch",
                "index": 1,
                "last": true,
                "tables": [
                    { "n": "Product" },
                    { "n": "Address" },
                    { "n": "Customer" },
                    { "n": "CustomerAddress" },
                    { "n": "SalesOrderHeader" },
                    { "n": "SalesOrderDetail" }
                ]
            }
        ]
    }

The ``ts`` value is the server timestamp at which the snapshot was generated. Clients use it to compute the delta they still need to fetch after applying the snapshot.

Filtered clients
-----------------------

When using row filters, snapshots are filter-specific. Pass the parameter values to ``CreateSnapshotAsync``:

.. code-block:: csharp

    var setup = new SyncSetup(allTables);
    setup.Filters.Add("Customer", "CustomerId");

    var parameters = new SyncParameters
    {
        { "CustomerId", "1001" },
    };

    await remoteOrchestrator.CreateSnapshotAsync(setup, parameters);

Generate one snapshot per parameter combination.

Configuring the server to advertise snapshots
------------------------------------------------

For new clients to pick up the snapshot, the sync server must know where snapshots live. Set ``SyncOptions.SnapshotsDirectory`` on the server side:

.. code-block:: csharp

    var options = new SyncOptions
    {
        SnapshotsDirectory = Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.UserProfile),
            "Snapshots"),
    };


HTTP mode (ASP.NET Core)
--------------------------------------------

Set the snapshot directory in the same ``SyncOptions`` you pass to ``AddSyncServer``:

.. code-block:: csharp

    var builder = WebApplication.CreateBuilder(args);
    builder.Services.AddControllers();
    builder.Services.AddDistributedMemoryCache();
    builder.Services.AddSession(o => o.IdleTimeout = TimeSpan.FromMinutes(30));

    var connectionString = builder.Configuration.GetConnectionString("DefaultConnection");

    var options = new SyncOptions
    {
        SnapshotsDirectory = Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.UserProfile),
            "Snapshots"),
    };

    var setup = new SyncSetup("ProductCategory", "ProductDescription", "ProductModel",
        "Product", "ProductModelProductDescription",
        "Address", "Customer", "CustomerAddress",
        "SalesOrderHeader", "SalesOrderDetail");

    builder.Services.AddSyncServer(new SqlSyncProvider(connectionString), setup, options);

    var app = builder.Build();
    if (app.Environment.IsDevelopment())
        app.UseDeveloperExceptionPage();

    app.UseHttpsRedirection();
    app.UseRouting();
    app.UseSession();
    app.MapControllers();
    app.Run();


Client side
^^^^^^^^^^^^^^^^^^^^

Nothing to do on the client. As soon as the server has ``SnapshotsDirectory`` set and a valid snapshot on disk, new clients pick it up automatically:

.. code-block:: csharp

    var s = await agent.SynchronizeAsync(progress);

Internally a fresh client triggers two passes:

* Apply the snapshot batches.
* Run a normal sync from the snapshot timestamp onwards to pull anything more recent.
